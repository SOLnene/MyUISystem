# 角色展示动画规范

本文记录当前项目已经采用的角色展示动画规则、资源路径、命名语义、工具入口和操作顺序。它描述的是当前实现；尚未接入的能力会明确标为“未接入”或“诊断用途”。

## 1. 当前系统边界

角色展示由三类数据共同组成：

1. `Body`：主要身体姿态，通常是 Humanoid Muscle 动画。
2. `Auxiliary`：角色专用辅助节点的 Transform 动画，例如衣摆、头发、挂点和扭转辅助节点。
3. `Face`：由 `FaceExpressionPreset` 驱动的 BlendShape 曲线。

运行时由以下组件协作：

- `CharacterPresentationProfile`：保存每个展示状态的动画配置。
- `CharacterPresentationController`：执行状态和阶段切换。
- `CharacterPreviewAnimator`：使用 Playables 同时播放 Body 与 Auxiliary。
- `FaceController`：播放一个或两个面部预设。
- `CharacterPreviewActor`：向控制器提供 Animator 和面部 Renderer。

Body 与 Auxiliary 不是两个 Animator Layer。`CharacterPreviewAnimator` 内部建立一个 `AnimationLayerMixerPlayable`：Body 位于第 0 层，Auxiliary 位于第 1 层。辅助动画记录的是绝对局部变换，所以第 1 层使用非 Additive 的覆盖模式；只有 Auxiliary Clip 存在时该层权重才为 1。

## 2. 状态与阶段

### 2.1 `CharacterPresentationState`

| 名称 | 含义 | 当前用途 |
| --- | --- | --- |
| `Default` | 默认展示 | 角色正常站立时的待机状态 |
| `TeamSwitch` | 队伍切换展示 | 队伍界面选择或切换角色时的角色专用展示 |
| `WeaponShow` | 武器展示 | 武器页使用的通用身体动画与角色辅助动画 |
| `RelicShow` | 圣遗物展示 | 圣遗物页使用的通用身体动画与角色辅助动画 |

`SpecialIdle/Show_01/Show_02` 已经纳入资源清单和 Runtime 目录，但尚未成为 `CharacterPresentationState`，也尚未接入“站立一段时间后随机播放”的调度逻辑。

### 2.2 `PresentationPhase`

每个状态最多包含三个阶段：

| Profile 分组 | 项目语义 | 当前原始资源后缀 |
| --- | --- | --- |
| `Enter` | 进入目标状态时播放一次 | `BS` |
| `Loop` | 进入完成后持续播放 | `Loop` |
| `Exit` | 离开当前状态时播放一次 | `AS` |

当前项目已经通过 `Furina_Presentation.asset` 验证并采用 **`BS → Enter`、`Loop → Loop`、`AS → Exit`**。原资源缩写的官方全称没有得到可靠确认，所以不要仅凭英文直觉解释或交换 AS、BS；配置时以本表为准。

`Default` 当前只有 Loop，Enter 和 Exit 为空。

### 2.3 `PresentationTransitionMode`

| 模式 | 实际行为 |
| --- | --- |
| `Immediate` | 跳过 Enter/Exit，立即播放目标状态的 Loop |
| `CrossFade` | 跳过 Enter/Exit，从当前 Body/Auxiliary 混合到目标 Loop |
| `Authored` | 完整执行“当前 Exit → 目标 Enter → 目标 Loop” |

`crossFadeDuration` 只用于状态之间的 `CrossFade`，不是 AS/Loop/BS 的播放时长。当前芙宁娜四个状态均为 `0.15s`。`Authored` 模式按 Clip 自身长度等待，不使用该值压缩或延长 Enter/Exit。

阶段等待规则如下：

- Body 存在时，以 Body 长度作为阶段结束时间。
- Body 为空、Auxiliary 存在时，以 Auxiliary 长度作为阶段结束时间。
- 两者都为空时，才使用 Face A/B 中较长的 `duration`。
- 因此同一阶段的 Body 和 Auxiliary 应当来自同一动作，并保持时长一致。

## 3. Profile 字段含义

每个状态的 `CharacterPresentationData` 都包含同一组字段：

| 字段 | 含义 | 是否允许为空 |
| --- | --- | --- |
| `enterBodyClip` | 进入段的主要身体动画 | 是 |
| `enterAuxiliaryClip` | 进入段的角色辅助节点动画 | 是 |
| `enterFaceA` | 进入段的第一份表情曲线 | 是 |
| `enterFaceB` | 进入段的第二份表情曲线 | 是 |
| `loopBodyClip` | 稳定状态的主要身体动画 | 是，但展示状态通常应配置 |
| `loopAuxiliaryClip` | 稳定状态的角色辅助节点动画 | 是 |
| `loopFaceA` | 稳定状态的第一份表情曲线 | 是 |
| `loopFaceB` | 稳定状态的第二份表情曲线 | 是 |
| `exitBodyClip` | 离开段的主要身体动画 | 是 |
| `exitAuxiliaryClip` | 离开段的角色辅助节点动画 | 是 |
| `exitFaceA` | 离开段的第一份表情曲线 | 是 |
| `exitFaceB` | 离开段的第二份表情曲线 | 是 |
| `crossFadeDuration` | `CrossFade` 状态切换的混合时间 | 否，允许为 0 |

### Face A / Face B

Face A 与 Face B 不是前后两个阶段，而是同一阶段同时应用的两份曲线，目的是组合不同面部区域，例如一份控制嘴、一份控制眼睛与眉毛。

- 两份预设都必须是 `CurveAnimation`。
- 两份预设的 `FaceRegion` 不能重叠。
- 区域重叠时 `FaceController` 会拒绝组合播放并输出警告。
- 只需要一份表情时放在 A，B 留空即可。
- 当前 `Furina_Presentation` 的所有 B 字段均为空。

### 5.2 可播放转换资源：`Runtime`

`Runtime` 保存经过路径标准化、并按当前诊断结论移除四条 UpperArmTwist 曲线的 AnimationClip 副本。

```text
Assets/Art/Animation/Runtime/
├─ Common/Girl/
│  ├─ Default/
│  ├─ Weapon/Sword/
│  └─ Relic/
└─ Character/Furina/
   ├─ Default/Auxiliary/
   ├─ Weapon/Auxiliary/
   ├─ Relic/Auxiliary/
   ├─ TeamSwitch/FullBody/
   └─ SpecialIdle/FullBody/
```

目录含义：

- `Common`：按体型、武器种类复用，不包含角色名绑定假设的身体动画。
- `Character/<角色>`：角色专用资源。
- `FullBody`：完整角色身体动画。
- `Auxiliary`：与通用 Body 同时播放的角色辅助节点动画。
- `Default`：默认待机。
- `SpecialIdle`：站立一段时间后触发的特殊待机，不等于 Default。

`Assets/GameData/ModelView/FacePreset/Runtime/` 已建立同类目录结构，但当前没有生成的面部资源，Profile 仍引用 `FacePreset/Extracted`。

### 5.3 当前 Git 管理状态

当前仓库规则是：

- `Assets/Art/Animation/Extracted/` 被根 `.gitignore` 忽略。
- `Assets/GameData/ModelView/FacePreset/Extracted/` 被根 `.gitignore` 忽略。
- 两个 `Runtime` 目录通过目录内 `.gitignore` 忽略生成资源，只保留 `.gitignore`。
- 工具、清单、Profile 和本文档应由 Git 管理。

这意味着当前动画和表情资源属于本机生成资产。需要特别注意：被 Git 管理的 Profile 会保存对本机 `.meta` GUID 的引用，而被忽略的动画/表情及其 `.meta` 不会随仓库传递。干净克隆无法仅靠重新生成保证得到相同 GUID；在多人协作或 CI 前，需要另行确定 Git LFS、私有资源仓库或可重建引用方案。

## 7. 动画分类规则

`Tools/AnimationClipAudit.ps1` 使用以下分类：

| 分类 | 含义 | 当前用途 |
| --- | --- | --- |
| `FullBodyHumanoid` | 含至少 20 条 Humanoid Muscle 属性 | 通用 Body 或角色专用 FullBody |
| `PartialHumanoid` | 有 Muscle，但不足完整身体阈值 | 需要人工检查 |
| `FullBodyTransform` | 主要身体 Transform 覆盖躯干、双臂和双腿 | Generic 全身动画候选 |
| `BodyPartial` | 只覆盖部分主要身体 Transform | 需要人工检查 |
| `AuxiliaryOnly` | 路径中包含 `+` 辅助节点，且无其他附件/未解析路径 | Auxiliary |
| `AuxiliaryWithAttachments` | 同时包含辅助节点与附件或未解析路径 | 可作为 Auxiliary，但必须继续检查未解析路径 |
| `AttachmentOnly` | 只有附件节点 Transform | 附件动画候选 |
| `UnresolvedOnly` | 只有 `path_<数字>` | 不可直接进入 Runtime |
| `InvalidNumeric` | 检出 NaN/Infinity | 禁止使用 |
| `Empty` | 没有有效绑定 | 禁止作为展示动画使用 |

清单审计的当前准入规则：

- Body 必须是 `FullBodyHumanoid`。
- Auxiliary 可为 `AuxiliaryOnly` 或 `AuxiliaryWithAttachments`。
- Auxiliary 如果仍含 `path_<数字>` 未解析绑定，不允许同步。
- 同名目标存在多个、资源缺失或数值非法时，停止同步，不自动猜测。

### 8.2 AnimeStudio 批量提取入口

文件：`Tools/ExtractPresentationAssets.ps1`

模式：

| `Mode` | 行为 |
| --- | --- |
| `Plan` | 只比较清单和项目资源，不调用 CLI、不写项目 |
| `Extract` | 只提取缺失资源到暂存目录 |
| `Audit` | 审计指定 RunPath 中已提取的结果 |
| `Sync` | 只同步已通过审计的结果 |
| `All` | 对缺失资源依次执行 Extract、Audit、Sync |

常用命令：

```powershell
# 查看当前缺失项
.\Tools\ExtractPresentationAssets.ps1 -Mode Plan

# 一次完成缺失资源的提取、审计和同步
.\Tools\ExtractPresentationAssets.ps1 `
    -Mode All `
    -GamePath "<游戏 Blocks 目录>" `
    -MapName "<对应 AssetMap 名称>"

# 对已有暂存结果继续审计和同步
.\Tools\ExtractPresentationAssets.ps1 -Mode Audit -RunPath "<暂存 Run 目录>"
.\Tools\ExtractPresentationAssets.ps1 -Mode Sync -RunPath "<暂存 Run 目录>"
```

补充参数：

- `-StagingRoot`：暂存根，默认 `F:\资源文件\PresentationExtraction`。
- `-RunPath`：指定某一次提取目录。
- `-UseFallbackCli`：改用清单中的 Fallback CLI。
- `-Overwrite`：同步时允许覆盖内容不同的已存在目标；默认拒绝覆盖。

动画使用 `AnimationClip + Convert` 导出；表情使用 `MonoBehaviour + Raw` 导出。工具按清单生成精确名称正则，只提取缺失项，不做宽泛导出。

#### 8.2.1 Body 动画链路

Body 分为通用身体动画与角色专用 FullBody 动画，但导出方式相同：

1. CLI 按精确资源名筛选 `AnimationClip`，并以 `Convert` 导出为 `.anim`。
2. `AnimationClipAudit.ps1` 必须将结果识别为 `FullBodyHumanoid`。
3. Sync 将原始结果放入 `Assets/Art/Animation/Extracted/`：通用动作进入 `Animations/Common`，角色动作进入 `<角色>/AnimationClip/FullBodyHumanoid`。
4. 在 Unity 使用“动画绑定路径转换”，保留 Humanoid Muscle，并把 Clip 内补充的 Transform/组件路径转换到 `ModelRoot/`。
5. 当前芙宁娜输出同时启用 `NoArmTwist`，生成到 Runtime 的 `Common/...` 或 `Character/Furina/.../FullBody`。
6. Profile 的 `BodyClip` 字段只引用 Runtime 副本。

通用 Body 例如 `Ani_Avatar_Girl_Standby`、`Ani_Avatar_Girl_Sword_UI_WeaponShow*`、`Ani_Avatar_Girl_RelicShow*`；它们按体型或武器类型复用。角色专用 Body 例如 `Ani_Avatar_Girl_Sword_Furina_TeamConfig_01_*` 和 `Show_01/02`。

#### 8.2.2 Auxiliary 动画链路

Auxiliary 是角色专用 Transform 动画，不能代替 Body 单独提供完整人体姿态：

1. CLI 同样筛选 `AnimationClip`，并以 `Convert` 导出 `.anim`；资源名必须包含角色名，例如 `Ani_Avatar_Girl_Sword_Furina_Standby`。
2. 审计结果必须是 `AuxiliaryOnly` 或 `AuxiliaryWithAttachments`，并且不能残留 `path_<数字>`。
3. Sync 将原始动画放入 `Assets/Art/Animation/Extracted/<角色>/AnimationClip/AuxiliaryOnly/`。
4. 在 Unity 使用“动画绑定路径转换”，将显式 Transform 路径转换到 `ModelRoot/`；当前芙宁娜同时启用 `NoArmTwist`。
5. 输出到 `Assets/Art/Animation/Runtime/Character/<角色>/<状态>/Auxiliary/`。
6. 将它配置到与同一动作、同一阶段对应的 `AuxiliaryClip`，由 Playables 与 Body 同时播放。

例如 WeaponShow 的正确配对是：通用 `Girl/Sword/WeaponShowBS` Body + 芙宁娜 `WeaponShowBS` Auxiliary。两者都属于 Enter，不能拿 Loop 或 AS 与之混用。

#### 8.2.3 Face Raw 链路

Face 不是 AnimationClip。AnimeStudio 中的 `Cs_Emo_Avatar_*` 是序列化的 `MonoBehaviour` 表情数据，因此流程不同：

1. CLI 按精确资源名筛选 `MonoBehaviour`。
2. 使用 `Raw` 导出，得到 `.dat`；这里的 Raw 表示保留原始序列化数据，不把它转换成 `.anim`。
3. Audit 只验证目标 `.dat` 唯一存在且非空。
4. Sync 不会把 `.dat` 直接放进 Profile，而是整理到本次 RunPath 的 `AcceptedFaceDat/<分组>/`。
5. 在 Unity 打开 `Tools/MyUISystem/角色展示/表情/导入 CsEmo DAT 文件夹`，将 `.dat` 转换成 `FaceExpressionPreset.asset`。
6. 输出到 `Assets/GameData/ModelView/FacePreset/Extracted/<分组>/`，再配置到 Profile 的 `FaceA`；确实需要组合两个不重叠面部区域时才使用 `FaceB`。

因此三种资源的核心区别是：Body 和 Auxiliary 都是 `AnimationClip + Convert`，区别由动画内容、审计分类和 Profile 通道决定；Face 才是 `MonoBehaviour + Raw → DAT → FaceExpressionPreset`。

### 8.3 AnimationClip 审计

文件：`Tools/AnimationClipAudit.ps1`

```powershell
.\Tools\AnimationClipAudit.ps1 `
    -InputPath "<AnimationClip 目录>" `
    -Recurse `
    -OutputPath "<报告.csv>"
```

`-CompanionRoot` 用来查找去掉角色名后可能对应的通用 Body Clip；省略时使用 InputPath。审计只读取 YAML，不修复动画。

### 8.4 模型根节点标准化

Unity 菜单：`Tools/MyUISystem/角色展示/模型/模型根节点标准化`

用途：为原始 FBX 生成独立副本，把“直接包含 `Bip001` 的内层角色根”重命名为统一的 `ModelRoot`，并同步 HumanDescription 和暴露路径。

规则：

- 不修改源 FBX。
- 不删除或压平层级，只统一内层根名称。
- 不改变节点 LocalPosition、LocalRotation、LocalScale 或 Humanoid 映射。
- 只支持 `Humanoid / Create From This Model`、未开启 Optimize Game Objects、且不含内嵌动画分段的初版场景。
- 不运行 HoyoToon Full Setup。
- 标准化副本以后普通 Reimport 会继续应用保存于 Importer `userData` 的规则。

目标动画绑定路径形如：`ModelRoot/Bip001/...`。

### 8.5 动画绑定路径转换

Unity 菜单：`Tools/MyUISystem/角色展示/动画/动画绑定路径转换`

用途：从 Extracted Clip 生成完整副本，将模型内部 Transform 绑定统一到 `ModelRoot/`，同时保留 Humanoid Muscle、AnimationEvent、Clip Settings 和其他未转换数据。

推荐设置：

- `待替换前缀`：通常留空。
- `目标前缀`：固定为 `ModelRoot/`。
- `输出目录`：拖入对应的 `Assets/Art/Animation/Runtime/...` 文件夹；工具会记住上一次目录。
- `同时转换模型内其他组件曲线`：只有明确需要 Renderer/组件曲线跟随路径时才开启。
- `排除 UpperArmTwist 曲线（诊断）`：当前 Runtime 资源开启。
- `验证模型`：建议指定 Animator 所在根，用于报告缺失节点和 Humanoid/Transform 控制冲突。

UpperArmTwist 排除项固定为：

```text
+UpperArmTwist L A01
+UpperArmTwist L A02
+UpperArmTwist R A01
+UpperArmTwist R A02
```

这是针对当前导入模型“运行时手肘压瘪”问题采用的兼容处理，不代表所有角色都必须删除这些曲线。新增角色时应先用验证模型和 PlayMode 对比确认。

工具用源资源 GUID + localID 标记自己的输出；再次处理同一源 Clip 会更新已有转换副本，并通过公开曲线 API 重新生成 Unity 的运行时绑定缓存。不要手工复制后冒充工具输出。

### 8.6 面部 DAT 导入

Unity 菜单：`Tools/MyUISystem/角色展示/表情/导入 CsEmo DAT 文件夹`

操作：

1. PowerShell 同步后，到该 RunPath 的 `AcceptedFaceDat/<分组>` 选择 DAT 来源目录。
2. 输出文件夹选择 `Assets/GameData/ModelView/FacePreset/Extracted/<分组>`。
3. 点击“开始导入”。
4. 检查创建、更新和失败数量，再将需要的 Preset 配入 Profile。

导入窗口会记住上一次来源与输出目录。它只处理 DAT → `FaceExpressionPreset`，不负责动画路径转换。

### 8.7 PlayMode 测试入口

选中挂有 `CharacterPresentationController` 的对象，使用自定义 Inspector：

1. 指定“测试角色”和“展示配置”。
2. 进入 PlayMode。
3. 点击“绑定测试角色与配置”。
4. 选择状态和 `Authored`，点击“切换到目标状态”。
5. 观察 Inspector 中的当前状态与当前阶段。

“单项测试”只验证单个身体 Clip 或表情，不等价于 Profile 的 Body + Auxiliary + Face 完整流程。最终判断必须以“切换到目标状态”的 PlayMode 结果为准，不能只依赖 Animation 窗口 Preview。

### 8.8 非正式链路工具

以下工具保留用于诊断，不属于当前推荐资产生产流程：

- `Humanoid Avatar 生成工具`
- `Humanoid Avatar 拇指映射验证工具`

它们生成独立 Avatar 资产，不修改源资源，但当前 Runtime Profile 使用的是“ModelRoot 标准化模型 + 路径转换动画”路线。除非专门验证 Avatar 映射问题，不要把这些工具生成的 Avatar 混入正式配置。

HoyoToon Full Setup 属于模型材质、网格和导入设置链路，不是 AnimationClip 提取、分类或路径转换工具。重新生成动画资源不要求重新执行 Full Setup。

## 9. 标准操作顺序

新增角色或补齐动作时按以下顺序操作：

1. 选择原始模型，打开 `Tools/MyUISystem/角色展示/模型/展示 Prefab 标准化`。
2. 确认从模型名推断出的角色 ID、体型、武器、队伍动画、Target Key 和 Model Address，点击“生成 Prefab 并登记角色”。工具会生成展示 Prefab、注册 Addressable、写入 Manifest，并尝试继续现有资源准备流程。
3. 运行 `-Mode Plan -CharacterId <角色 ID>`，确认缺失项与目标路径。
4. 对缺失项运行 `-Mode All`；如果中断，则使用同一 RunPath 分别执行 Audit、Sync。
5. 回到 Unity，再运行“从资源清单准备并生成”，完成动画转换、表情导入、Profile、PreviewDefinition 和 ModelPreviewDatabase 登记。
6. 确认角色实际使用的模型是工具生成的展示 Prefab，并使用该副本自带的有效 Humanoid Avatar。
7. Profile 只引用 Runtime AnimationClip；表情当前引用 FacePreset/Extracted。
8. 按 `BS → Enter`、`Loop → Loop`、`AS → Exit` 配置三个阶段。
9. 使用 `Authored` 在 PlayMode 验证完整状态路线，再分别检查 `Immediate` 和 `CrossFade`。

## 10. 验收清单

- `Plan` 没有缺失资源。
- Body 分类为 `FullBodyHumanoid`。
- Auxiliary 分类符合清单要求，且没有未解析 `path_<数字>`。
- Runtime Clip 的目标路径从 `ModelRoot/` 开始。
- 同一阶段 Body/Auxiliary 时长匹配。
- Loop Clip 的循环设置正确。
- 没有 `Binding warning`、缺失节点、重复目标绑定或 NaN/Infinity。
- Animation Preview 和 PlayMode 姿态一致。
- 手臂、手肘、手指以及衣摆/头发辅助节点没有异常变形。
- Face Preset 的曲线能在当前角色 `Brow`、`Face`、`Face_Eye` BlendShape 上找到目标。
- 双 Face 组合时 Region 不重叠。
- `Authored` 路线的退出、进入、循环顺序正确，且 AS/BS 没有填反。
