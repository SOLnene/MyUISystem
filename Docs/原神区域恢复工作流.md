# 原神区域恢复工作流

## 当前样板

`mondstadt_2_-1` 使用本机客户端的蒙德城合并模型、所在区块合并地形及各自贴图，目标范围为 1024 × 1024 Unity 单位。

当前质量层级是客户端 HLOD。地形和城市可作为区域底图，合并模型内的建筑没有独立门、NPC、宝箱、任务或副本逻辑。近景材质和网格精度仍需后续替换为更细的资源。

## 文件职责

- `Tools/GenshinRegionManifest.json`：工具路径、资源索引、区域范围、资源清单、摆放信息和来源。
- `Tools/ExtractGenshinRegion.py`：扫描索引、精确提取、校验文件、同步到项目。
- `Assets/Script/Game/Editor/GenshinRegionImporter.cs`：在 Unity 中导入、创建材质和碰撞、生成场景及覆盖率报告。
- `.codex_tmp_frame_analysis/genshin_regions/<区域>/<运行编号>/`：每次执行的计划、日志、审计和 Unity 验证结果。

资源使用现有的 `Assets/Art/Model`、`Assets/Art/Material` 和 `Assets/Scenes` 目录。模型目录当前被项目 `.gitignore` 排除，可使用清单在本机重新生成；本流程没有修改忽略规则。

## 执行

需要 Python 3.11 或更新版本，以及 `msgpack`、`lz4`。已安装模块的机器可直接运行；也可以通过 `--python-deps` 指定已有模块目录。

在项目根目录执行：

```powershell
python Tools/ExtractGenshinRegion.py --mode all
```

当前机器已有分析依赖可复用：

```powershell
python Tools/ExtractGenshinRegion.py --mode all --python-deps .codex_tmp_frame_analysis/shader_pydeps
```

随后在 Unity 中执行：

```text
Tools > Genshin Region > Build Latest Extraction
```

菜单读取当前区域最新的 `import_plan.json`，生成独立场景并在 Console 输出场景和报告路径。场景名称以 `GenshinRegion_mondstadt_2_-1` 开头。重复生成会使用新场景名，保留旧场景。完成后恢复原活动场景及其未保存内容；在 Project 中打开新生成的场景查看。

原始导出文件已存在且内容一致时会复用。若项目中存在同名但不同内容的模型或贴图，同步阶段会停止，保留现有文件。应核实版本及资源来源，再另建运行计划或调整清单中的新资源名称。

## 分阶段执行

先创建提取计划：

```powershell
python Tools/ExtractGenshinRegion.py --mode plan --python-deps .codex_tmp_frame_analysis/shader_pydeps
```

命令输出本次运行目录。后续使用该目录：

```powershell
python Tools/ExtractGenshinRegion.py --mode extract --run <运行目录>
python Tools/ExtractGenshinRegion.py --mode audit --run <运行目录>
python Tools/ExtractGenshinRegion.py --mode sync --run <运行目录>
```

每个运行目录包含：

1. `extraction_plan.json`：精确资源名、来源包、Path ID、包内偏移及工具版本。
2. `extracted/` 和 `extract.log`：原始提取结果及日志。
3. `audit.json`：文件哈希、OBJ 顶点和三角形统计、贴图尺寸及完整性。
4. `import_plan.json`：已同步到项目的资源及其引用路径。
5. `unity_build_*.json`：场景路径、碰撞覆盖率、几何数量和原场景状态。

工具同时检查进程退出码、日志中的导出错误和实际输出文件。AnimeStudio 的退出码为 0 并不能单独证明提取完成。

## 区域摆放规则

OBJ 导出涉及 X 轴方向转换，Unity 导入后恢复到项目坐标方向。当前地形使用本地 X/Z 重新生成 BaseMap UV，城市模型保留原始图集 UV；两类资源不能使用同一种 UV 处理。

蒙德城的位置参考 HoyoMap 的安卓布局清单，来源及内容 SHA 已记录在配置中。样板将城的参考位置 `(2275, 263, -783)` 减去区块偏移 `(2048, 0, -1024)`，得到区块内位置 `(227, 263, 241)`。

第三方布局应与当前客户端网格交叉检查。零位置、缺失位置或版本不一致的条目应先列为待核实，避免直接应用到区域中。

参考：

- https://github.com/flatypus/hoyomap/blob/main/manifests/all_hlod_manifest.json
- https://github.com/flatypus/hoyomap/blob/main/public/index.html

## 扩展到其他区域

在配置的 `profiles` 中新增区域，并调整 `activeProfile`；也可通过提取命令的 `--profile` 选择区域。需要声明：

- 区块坐标和尺寸。
- 目标 Mesh、贴图的精确资源名及类型。
- 每个模型的贴图、UV 模式、相对位置和角色。
- 布局数据来源与可接受的地表覆盖率。

位置和对应材质未确认的资源应保留在调查阶段。新增区域之前，先验证该区块的地形合并网格及 BaseMap 存在，再扩展建筑、植被或其他局部模型。

本流程只生成独立区域场景，不修改 UIType、Addressable key、ResourceManager 或现有场景加载流程，也不自动加入 Build Settings。

## 验证边界

Unity 在区块内部做 41 × 41 个向下碰撞采样，报告命中数量和未命中位置。该数值表示采样位置的表面覆盖情况；角色坡度、台阶、跨缝移动、NavMesh 和水面规则仍需游戏控制器验证。

保存场景后还应重新加载，检查资源引用、地形及城市的位置关系，并查看总览和近景截图。当前 Standard 材质只使用已提取的颜色贴图，未还原原版环境 Shader、动态水体、草和天气。
