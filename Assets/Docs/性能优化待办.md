# 性能优化待办

## PERF-EQUIP-TRANSITION-001：角色到武器界面切换卡顿

状态：暂缓

### 当前进度

- `ModelViewer` 的镜头状态和实际写入入口已经统一。
- 普通 CameraPreset 和推镜共用同一套镜头过渡逻辑。
- 角色到武器界面的推镜只改变 Z，不修改 Pitch、Yaw 和 FOV。
- 尚未处理镜头运动期间的主线程长帧。

### 已知现象

- 重复进入武器界面时仍可能出现镜头运动不连续，因此问题不应只归因于首次资源加载。
- `UIManager.Open` 在镜头运动期间同步触发 `EquipDetailView.OnOpen`。
- `EquipDetailView.OnOpen` 当前会重新创建 ViewModel、执行根 View 和子 View 绑定，并应用初始页面状态。
- 在获得 Profiler 数据前，不通过调整镜头曲线掩盖问题。

### 待处理

1. 在 `CharacterDetailView` 调用 `UIManager.Open` 的同步范围添加 ProfilerMarker。
2. 分阶段测量 `EquipDetailView.OnOpen`：
   - CreateViewModel
   - BindRoot
   - BindChildren
   - ApplyInitialState
   - BeginOpenTransition
3. 测量武器模型提交阶段：
   - EnsurePreloadedAsync 恢复后的同步工作
   - TryActivatePreloaded
   - ApplyPreviewCamera
4. 根据 Profiler 结果判断主要来源：
   - 重复绑定或 ViewModel 创建
   - Canvas/Layout 重建
   - GC Alloc 或 GC.Collect
   - 资源主线程集成
   - Shader 首次使用
5. 根据结果评估 `Prepare / Commit / Finalize` 页面打开流程。
6. 主线程长帧处理完成后，再评估镜头的长帧视觉时间策略。

### 验收标准

- 连续多次进入武器界面时不出现明显镜头停顿。
- 60 FPS 目标下，切换期间单帧尽量不超过 16.67ms。
- 重复切换时业务代码的 GC Alloc 接近 0。
- 推镜期间不执行可提前完成的大量页面创建、绑定或资源集成工作。

### 恢复方式

后续任务中搜索或引用 `PERF-EQUIP-TRANSITION-001`，从本记录继续。

## TEAM-EDIT-001：队伍编辑界面后续接入

状态：待实现

### 当前进度

- 主菜单的队伍入口已经通过 `UIManager` 打开 `TeamEditView`。
- `TeamEditView` 负责创建队伍展示场景、切换主镜头，并在关闭时恢复现场。
- 四个角色位目前共用同一个角色选择面板；点击任意角色位可以打开面板，返回操作会优先关闭面板。
- 角色选择面板暂时复用 `ItemSlot` 作为角色图标占位，尚未接入角色数据和选择结果。

### 待处理

1. 点击角色位时记录目标队伍槽位，并把槽位上下文传给角色选择流程。
2. 将通用选择界面接入角色数据源，继续复用 `ItemSlot` 展示头像、选中态和不可用态。
3. 选择角色后回写目标槽位，并刷新队伍展示模型；补充替换、清空和重复角色约束。
4. 明确编辑中的临时队伍与已保存队伍的数据边界，再接入确认、取消和持久化。
5. 完善角色模型加载、站位、朝向和镜头构图，处理页面快速开关时的异步资源生命周期。
6. 确认通用选择界面最终采用 `TeamEditView` 内部面板还是独立 UI 栈；当前版本保持内部面板，不新增 `UIType`。
7. 补充主菜单进入、选择面板开关、页面返回和重复打开的 Play Mode 验证。

### 验收标准

- 点击不同角色位时，选择结果只更新对应槽位。
- 打开和关闭选择面板不会重复注册监听，也不会改变 `UIManager` 页面栈层级。
- 关闭队伍页面后，队伍展示实例被释放，进入页面前的主镜头状态被正确恢复。
- 连续进入和退出队伍页面时不残留模型、相机或异步加载任务。

### 恢复方式

后续任务中搜索或引用 `TEAM-EDIT-001`，从本记录继续。
